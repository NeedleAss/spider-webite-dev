## 02｜旧 V4 与本次需求：必须明确覆盖关系

这次不是把所有不满意都归为开发错误。旧 V4 明确允许简化人物、固定 DEMO 屏幕、最后照片对照，并要求自由探索不因悬停完全拆开。用户本次改变了这些选择，应更新契约，不应让 Codex 同时遵守互相冲突的两套要求。[S5][S6]

| 项目 | 旧 V4 / 当前实现 | 本轮新决定 |
|---|---|---|
| 自动演示 | 滚动 + 章节跳转 + 局部动画暂停 | 新增真正的全片自动播放、逐页讲解与离线 MP4 |
| 自由探索入口 | 进入后已展开，不悬停全拆 | 默认完整；桌面悬停意图触发展开；选中后保持；触屏显式展开 |
| OLED | 固定 DEMO，不生成健康数值 | 允许明确标记的脚本化模拟 HR / SpO₂；与接触状态绑定 |
| 人物 / 手指 | 原理用简化形体 | 桌面场景中的成人与手按米制比例制作，近景可用高质量预渲染 |
| 末页 | 查看未完成装配照片 | 删除公开照片入口，最终整机定格，交给现场拿出实物 |
| 旋转 | 已有水平旋转与缩放 | 保留；补上下方查看、部件近景构图与可打断过渡 |
| 实物声明 | 软件与实物分开 | 继续保留；模拟场景不变成实测录像 |

制作时建立 `docs/V5_DECISIONS.md`，将上表写成当前唯一入口。不能因为旧规范不允许示例数值，就把用户的新需求拒绝掉；也不能把允许示例数字解释成可以伪造实时健康数据。

## 04｜代码问题的最小修复与验收

### R01：确认必须跟随 robot 数据年龄，而不只是任何 telemetry

位置：`js/app.js:158–170` 的 render / stopStatus 调用，`js/state.js:126–142` 的 applyTelemetry，`js/display-semantics.js:2–6`。

复现：t=100000 ms 收到 robot ESTOP；t=102000 ms 只收到 health 子块。state 正确保留旧 robot，并只更新通用遥测时间。但 render 将通用 stale=false 传给 stopStatus，结果仍是 `device-reported`。当前 robot 已经 2000 ms 未更新，不能因为健康信号继续到达而把它当作新确认。本轮 T08 FAIL 可直接复现；普通断线、完整静默和回放优先级等对照通过。[S7][S8][E1]

最小修改：增加独立 `robotStale`，结合连接状态、lastRobotTs、负年龄异常和 robot 的允许期限；急停“设备上报”必须使用这条新鲜度。模式/执行状态显示也应与自己的数据时钟一致。继续保留本地急停锁，绝不因显示过期解除控制。本包候选只验证新鲜度判定，不包含已经合入 app.js 的补丁。

当前真实固件通常每次发布 robot 子块，因此这个问题主要发生在部分遥测、协议演进或异常桥接路径。不要将本次合成路径宣称为已发生的实车故障。浏览器需加 health-only / imu-only / PPG-only 三类用例；最后新 robot 数据到来时才恢复确认。

### R02：展开不应该只是把四个外层部件移走

位置：`presentation/story/timeline.js:43–53` 的 partOffset，`presentation/scene/robot.js` 的 apply/cables。

完整开壳状态里只有 lid/display、shell、board-frame 有默认 offset；主控、主板支架、多数电子件和执行件保持安装位置。Inspect 又直接调用相同的开壳状态，因此它并不是一套独立的清晰爆炸布局。用户反馈壳体与板件重叠，与这种有限位移策略存在对应关系；本轮没有直接测得最终像素遮挡面积，不能写成“已确认全部网格穿模”。[S9][S10][S11]

最小方向：区分剧情开壳、总览爆炸、选中聚焦三套布局。第 08 节规定空间间隙、重点件遮挡、相机适配与线束处理。单纯乘大所有 offset，可能让部件更靠相机后方或跑出视口，不是完整修复。

### R03 / R06：选择镜头、效果和全角度查看

位置：`presentation/app.js:130–147` selectPart/inspectReset/enterInspect，以及 boot 中 OrbitControls 配置。

现在 selectPart 直接覆盖 camera.position 和 controls.target，所有零件统一采用方向 (-1,0.5,0.55)，不能保证镜头、屏幕或板面朝观众；选择后的视域/回波也未继续调度，因为进入 Inspect 时全隐藏，frame 的 inspect 分支只有 controls.update。[S9]

做 per-part / per-instance focusShot：目标、观察方向、距离、必要隔离、说明与效果。用约 0.65–0.9 s 的可打断过渡作为美术起点，用户拖动即取消过渡；取消不能残留另一个相机控制器。缩放距离按包围球和可用视口计算，而不是固定乘对角线常量；右侧说明栏与手机下方抽屉都要进入可用画幅计算。

**当前水平方向 360° 已经允许，缩放也存在。** 不要为了修它重新造控制器。限制在 maxPolarAngle=0.88π，即底部还留约 21.6° 不可到达区域。Inspect 使用接近 0 到 π 的极角范围，或明确的翻看底部视图；不要让地板遮挡模型底部。保持模型 root 不为观察角度随意变形。[S9][E2]

### R05：跨章的相机连续，不等于整个场景连续

positionCamera 的 vision 末尾与 range 开头匹配，独立 T15 通过。但 updateMotion 每次先把 root 清零；完整响应后 root 仍有约 26 mm 平移与 0.2 rad 转向，进入 range 会直接归位。这里只确认代码变换不连续，具体跳变感仍需录像验收。[S9][S10][E1][E2]

统一导演后，每个世界变换由时间求出。允许明确剪辑时切换镜头，不允许在一个看似连续的拉远镜头中瞬间重置车的位置。相机、机器人、人物、杯子、手与屏幕都必须共用事件状态。

## 05｜控制台确实修改过：在哪里、改了什么

产品展示位于 `presentation/`，实际控制台仍是仓库根目录 `index.html`，不是产品页中的隐藏章节。当前展示页 header 只有自由探索，并没有明确的控制台导航。[S6][S12]

开发环境运行根目录静态服务后，两个入口分别为：

```text
http://127.0.0.1:8765/presentation/     产品展示
http://127.0.0.1:8765/?transport=mock  浏览器模拟控制台
```

真机仍使用由已验证主控固件提供的同源控制台，按现场实际地址访问；不能因为电脑上有产品页，就静默跨源连接机器人。不要把示例地址当作已核验的现场连接。

本次控制台已做了有意义的改动：立即锁本地输入，同时区分发送失败、等待设备、设备上报；断连后不继续维持确认措辞；回放标题优先于实时 disconnected；PPG 保留源批次时间并明确 arrival-estimate；回放使用独立时间平移，绘图不会把网络延迟直接当采样时间。[S7][S8][S13]

这些并非只是改标题。仓库浏览器 fixture 检查了丢弃急停发送、设备上报、完整静默、回放隔离和 PPG 延迟。它还没有覆盖本轮 R01 的“其他 telemetry 继续但 robot 静默”。[S14]

下一版建议入口清楚分工：产品 / 演示 / 探索；辅助入口“操作台”。打开操作台前让用户选择“浏览器模拟”或“进入设备控制台”，标明数据源。退出影片或进入操作台不自动切 MANUAL、不恢复旧目标、不连接已保存但未经确认的设备。控制台无需套用影片中的复杂景深、玻璃或小字号。

控制台最后检查重点：44 px 以上主要按钮、稳定可达的急停、当前 owner/只读状态、目标速度而非“实测轮速”、video 与 metadata 失效、OLED/健康源龄、回放不发命令。已通过的软件逻辑不为美术重写；G01 及实体停止仍按原流程验收。[S4][S7]

## 06｜不要“录一遍滚屏”：一套内容，三种展示方式

建议导航和技术分工如下：

```text
同一套资产 + 分镜时间 + 演示事件 + 说明文本
     ├─ 滚动阅读 Scroll：观众自行推进，保留细节动画
     ├─ 发布演示 Deck：全屏、上一页/下一页、自动播放/暂停
     └─ 影片 Film：可独立播放的 MP4，网页内也可播放
独立 Inspect：完整模型、悬停展开、360°、缩放、部件聚焦
独立 Console：真实/模拟控制，绝不由以上展示事件驱动
```

用户不需要额外维护一份 PowerPoint，网页 Deck 就可以提供逐页讲解的操作语义。它与滚动页面共享内容，而不是强行让浏览器每隔几秒滚一个固定像素值。

### 一条主时间轴，而不是互相追赶的两个时钟

当前 progress 决定构图，clock 决定局部事件；章节或 beat 变化会把 clock 清零。因此一次快速滚动可看见事件结果，另一次停留可能看到不同阶段。旧版容许这种探索方式，但它不适合可重复的成片。[S9]

改为 `evaluate(t, viewport, quality)` 产生完整 scene state：镜头、整车/部件/人物姿态、可见性、声波进度、手接触、OLED 内容、字幕。全部关键结果可随机 seek；同一 t 不依赖过去 rAF 次数。Scroll、Deck 和视频是输入适配器，不分别计算同一事件。

Scroll 将章节内位置映射到 t；可在明确的小片段允许循环，但循环相位也必须是可查询的局部时间。Deck 用显式播放时钟或逐章推进到 hold 点；按一次键完整播放该镜头，再停在讲解帧。影片用固定时间采样导出；网页播放 MP4 时媒体时间为主，不再跑另一个 rAF 累加时钟。

进入 Inspect 时暂停导演与声音，保存语义时间与来源模式；退出返回原位置并保持暂停，交给用户继续。切后台、资源不足、上下文丢失均暂停，不在恢复时跳过十几秒关键镜头。当前 dt 上限 .05 s 用来保护局部动画可以，但不能让成片声音与画面分别累计出不同总时长。

浏览器可能限制带声音的自动播放，因此“开始演示”用一次明确点击；接着全程自动，不要求逐章滚动。video frame callback 可帮助同步帧呈现，但不等于任意 currentTime seek 都帧精确。[W4][W5]

## 07｜96 秒影片：从产品特写，进入真实尺度的桌面

建议创意主线：**很小的机器人，很清楚的回应。** 只用一张桌、一位坐着的人、一个杯子和同一组光线。减少布景变化，把视觉冲击集中在两次尺度揭示：由内部回到整机，再由整机回到人的日常环境。

以下是制作候选，不是已产生成片；每一段都有事件、结果和停留点。

| 时间 | 镜头与动作 | 字幕/讲解重点 | Deck 停留 |
|---|---|---|---|
| 00–07 s | 黑场中轮廓光出现；白色正面，双端面和镜头明确，顶部 OLED 微亮 | CareRover／让感知，成为行动 | 5 s |
| 07–20 s | 顶盖与 OLED 一起抬升；壳体沿路径让开；主控、感知、轮组分区显露 | 小小机身，各有分工 | 18 s |
| 20–29 s | 相机与超声端面两个近景，材质与功能锚点准确；不过度抛光 | 看见位置。听见距离 | 27 s |
| 29–40 s | 按路径收拢；摄影机持续后退，接触阴影显露为桌面；房间与坐姿成人逐渐进入 | 尺度在环境中自然揭示 | 38 s |
| 40–55 s | 成人小幅改变位置；画面层的检测框出现；机器人先朝向再响应；目标离开后停止 | 有依据，才回应 | 53 s |
| 55–69 s | 桌面出现杯子；波从端面到杯壁，再返回；机器人停止，沿既定空旷路径横移/绕过 | 前方测距／受限场景动画 | 67 s |
| 69–80 s | 同一成人的手伸来，手腕/掌部可见，指腹轻触侧面传感器；局部光学示意 | 接触 → 采集；时间经过剪辑 | 78 s |
| 80–89 s | 摄影机沿机身抬到顶部 OLED；显示同一模拟结果；松手后清空/回待机 | HR 72 BPM、SpO₂ 98%／模拟读数 | 87 s |
| 89–96 s | 手退出，回到完整正面，干净背景；结束定格，不再打开照片 | CareRover／现场展示 | 96 s |

发布片字幕可更少，答辩 Deck 保留短解释。末尾至少数秒稳定留给讲解者拿出实物；不自动打开操作台，不循环回片头，不播放未准备好的下一段。

**最先验收的不是整片占位，而是 29–40 s 的拉远落桌、69–89 s 的手部到 OLED，以及清晰的 Inspect 展开。** 这三段通过后，再补整片统一声音、字幕和色彩。

## 08｜展开布局：三维间隙与二维可读性分别解决

### 三套布局，不能复用同一个 open=1

StoryOpen 保留工程层次，适合讲内部结构；InspectExploded 给用户看清与选择，允许更大空间；PartFocus 只强调选中件和必要参照，可暂时隔离其他物体。源 CAD rest TRS 不变，姿态由当前布局计算，收拢精确恢复。

桌面展开的建议分区：顶盖/OLED 在上方作为一组；外壳放到右后方独立槽位；主板外框和支架不要与主控叠在同一视线；控制、电源、前方传感和侧面传感分左右层级；轮与舵机按实例朝外展开，不用随机方向。所有位移沿具有解释意义的路径进行，外壳先离开包络再侧移，不能从板件中直接穿过去。

用完整外观包围盒初始化距离，但不要只比较盒子：薄壳的 AABB 本来就会包含内部空区。先宽相位筛出风险对，再对需要独立分离的网格作间隙/穿透检查；设计上应保持接触的螺丝、板与支架列入白名单。终态无穿模不代表过渡路径无穿模，必须沿动画采样。

### 主视图可读，不承诺所有观察角度零投影重叠

有限空间中多个物体从某些方向看必然重叠，因此“360° 每一个角度都完全无重叠”不是合理验收条件。要求应为：独立件三维无穿透；预设总览视角能区分功能组；选中后重点件无遮挡；用户可以旋转换角度。

建议起始指标：独立功能组空间间隙约 0.1H–0.2H（H 为整车高度），默认总览关键轮廓间有 16–24 CSS px 的可读间隔；聚焦件可见面积目标 ≥90%。这些是项目美术验收目标，可调，不是行业标准。用对象 ID mask 测可见比例，不能仅凭 2D 包围框相交就宣布物体穿模。移动端缩成更宽的层级/分页探索，别让所有零件再挤成一团。

### 线束与拾取

大拆解不把线拉成橡皮筋。重点线束保留真实端点近似并改变弧线；超过可用长度时清楚淡出或表现断开连接器，说明连接示意简化。测量的是曲线弧长，不能只用首尾直线距离代替。dim 的物体仍是实体，必要时使用“仅看此部件”而不是全部半透明；不让隐藏件抢射线。

## 09｜自由探索的完整交互契约

默认 ASSEMBLED，无随机自转。细鼠标进入稳定的模型区域，约 200 ms 意图延迟后展开；离开整个探索区域且无选择，约 350 ms 后收拢。说明抽屉属于同一交互域，移动到文字上不能立刻收回。按住拖动、双指缩放或对话框打开时，不因边界 enter/leave 触发新的展开。

状态采用 `ASSEMBLED → EXPANDING → EXPLODED → FOCUSING → SELECTED → RETURNING`，中途可逆。进入 SELECTED 后固定展开；关闭说明先回总览，主动“完整装配”再收拢。触屏用显式展开/收拢按钮，不假装有 hover；键盘目录与回退同等可用。

360° 水平旋转、上/下方查看、鼠标滚轮及双指缩放是必要功能。Inspect 内接管手势，外部仍有稳定的退出按钮；退出恢复先前影片/滚动语义位置。保持按钮 ≥44 CSS px，并确认手机底部安全区和横屏高度。

部件聚焦不应让点击引起无缓动跳跃。每个 part 有自己的观察基准：OLED 看屏幕法线，相机看镜筒与板面，超声看双端面，轮子看轮面/滚子，主控看接口与屏蔽罩。相同类型的多个实例还要应用各自安装旋转。缓动开始时从当前镜头采样，用户再次点选或拖动可安全中断；不能同时让 OrbitControls 和 tween 争写相机。

自由探索时保留“原理动画”开关，但默认只运行所选部件效果。说明不需要重复一整章影片；给用户一个明确、短小的因果演示即可。导出影片、网页滚动和探索使用同一外观资产与锚点身份，避免三种模式出现三台不同的机器人。

## 10｜真实尺度：不能把“小人”只放大几倍就结束

当前 world person 由 5 mm 半径头球、胶囊躯干和两条腿组成，最高点约 41 mm、最低点约 −5 mm，总高约 46 mm。它是场景中的人物，不是图像平面上的图标。原 CAD 保存网格整体高度本轮算得约 129.54 mm；衍生外观还要另测。这解释了为什么用户看到“人比机器人小”。[S9][E2]

人物/手/桌/杯与机器人统一使用米。影片可以选择约 1.72 m 身高的成人、约 0.74 m 高桌面与约 0.10 m 高杯子作为美术尺寸，但应标记为场景设定，不是统计均值或现场测量。机器人不按画幅需要放大缩小；从特写拉远到桌面靠摄影机移动与适当焦距，而不是把 robot.scale 从 10 动画缩回 1。

落桌位置按 `rootY = tableTopY − lowestContactY` 求出，先检查轮与桌面接触，再加阴影。不能把原 root=0 当轮底平面。相机 near/far、灯光范围和阴影相机也要适配由厘米级特写到米级房间；当前摄影机 far=5 m 和小范围阴影不是整个房间的默认配置。[S9]

### 成人脸必须真的落在低位镜头可见范围

机器在桌面，镜头低，坐着的人脸高；光轴正确不等于能看到人。对所用虚拟相机，检查脸部包围盒是否在视锥内，粗略必要条件为 `abs(faceY − lensY) <= horizontalDistance × tan(verticalFov/2)`，之后还要检查左右与遮挡。

真实 FOV 未标定时不要填成设备参数。可以调整演员坐姿、轻微前倾和桌面距离，使镜头中真实出现脸；不能偷偷把机器人镜头旋向上方，或把正常成人压扁适配原镜头。影片中标识视域/识别为演示，不给出未经验证的“这个位置真机必能跟随”。

优先制作同一个房间的半身坐姿成人和前臂，避免把预算花在从未出现的全身衣物。高质量影片使用许可明确的人物/手部资产或团队自有素材，网页探索仍保留轻量机器人。近景中的脸、皮肤与手形达不到要求时，可用预渲染而不是继续堆程序胶囊。

## 11｜人、摄像头、杯子：让动作讲同一个故事

### 摄像头：高科技观感，不伪造激光硬件

可用薄的视域光场、跟踪角标、低强度扫描线和图像平面反馈形成技术感。它们是“感知可视化”，不是摄像头物理发出激光。原型不是 LiDAR，不能让观众误认为有主动激光扫描。四角框应绑定真人头部在虚拟镜头中的投影，目标出视野后消失，不能固定粘在世界原点。

同一时间事件驱动人物移动、检测有效性与机器人响应。沿用先朝向、再平移、失去目标停止的叙事，不临时增加搜人或身份识别。世界人物与镜头内的小图标分层命名，不能混用尺寸或把图标当成人站在桌上。

### 超声：波必须真的到杯子，再返回

一两个细波前/短弧从模块朝外传播，冲击点落在杯子的可见表面，再有返回波。传播终点来自场景杯子的几何/指定命中点，不是另一个透明平面漂在杯子前。波前始终与传感器法向一致，使用深度测试，避免穿过机身后还在前景出现。

影片放慢传播是解释手段，应标为“回波示意”。收到结果后先让车停止，再按预先确认空旷的右侧路径横移/绕过。不能只让声波播放而整车始终不响应，也不能同时把杯子穿过去。两端 TX/RX 未确认时继续用模块级发出/返回，不擅自指定左右身份。

### 桌面风险不能被影片美化掉

前方测距不等于桌沿/跌落检测。动画轨迹远离边缘，不设计“冲到桌沿自动刹停”的镜头。真机桌面演示必须另有现场验证的边界、接管和动力断开条件；仅凭影片中的杯子动画不能认定实车具备相同路径能力。本轮不新增防跌落功能来扩大范围。

## 12｜真实手部、接触光学与 OLED：一次事件到底

“血量”在这里应改成 **血氧饱和度 SpO₂**。MAX30102 用于心率/血氧相关光学采集，不是测全身血液量。Analog Devices 官方资料支持红光/红外、光电检测的原理说明，但不替代本项目整机的测量准确性验证。[W3]

### 手不只是一个指尖胶囊

当前指形胶囊约 30 mm 长、8 mm 宽，是简化道具；加了指甲和褶皱仍没有手掌、关节、腕部与动作来源。[S15][E2]

新镜头从同一坐姿成人的前臂延伸到手，保留掌指过渡、指甲方向、皮肤粗糙度和关节弯曲。指腹接触传感器接触面，而非指甲或指尖正穿过玻璃。用明确 contact anchor 驱动指尖/手骨骼，目标面姿态来自健康模块世界变换。接近、减速、轻触、保持、离开分阶段；接触时有细小压感或稳态停留，不让整个手上下“抽动”。

红/红外只在接触局部做短解释。红外本来不可直接看见；以假色表示时写清“光学原理示意”。不要让血氧模块向手外发射几束远距离激光，或者隔着空气就跳出结果。

### 新读数是“有标识的演示值”，不是“假实时数据”

建立独立 `healthDemoState`：idle → approach → acquiring → valid → released。只有同一事件进入 valid 后，顶部 OLED 和可选字幕才显示同一组脚本数值，例如 72 BPM、98%（仅为制作示例）。整个片段持续标识“模拟读数 · 非医疗用途”；缩短测量等待用剪辑表达，注明“采集过程已压缩”，不能暗示实际只需数秒。

镜头转向顶部时不重新抽随机数，不因为章节变化重置测量。手指离开后清空或回到待机；回到更早时间点也能恢复同一采集状态。膜拜“数值动起来”不如状态正确。模拟数据模块禁止 import 控制台 state/transport，绝不能写入 live telemetry 或录制成设备证据。

当前 OLED 纹理是在 createAppearance 里一次画出的 DEMO 字样，没有动态状态接口。[S16] 最小修改是保留纹理与材质身份，暴露 `setDemoScreen(state)`；只在文字变化时重绘已有 CanvasTexture 并标 needsUpdate。不要每一帧创建 canvas、texture 和材质；合批时保留动态屏幕引用。屏幕维持蓝色单色像素风，不变成全彩手机屏。

## 13｜Apple / NVIDIA 参考如何转成自己的设计

本轮查阅 Apple 官方产品页、Apple Events 入口及 NVIDIA GTC keynote 页面。对官方页面可见的产品图文组织与媒体入口作参考；本环境没有完成官方长视频逐帧播放，下面是本项目的创作方案，不冒称复刻某个发布会镜头、剪辑参数或底层实现。[W1][W2]

从 Apple 的产品表达中提炼：产品为唯一视觉中心，整机与特写交替，技术点最后落到人的使用情境。从 NVIDIA 的技术发布表达中借鉴“实物与数字解释切换”，但不复制其复杂仪表、品牌绿色或任何不属于本项目的 AI 能力。素材、音乐、人物和字体均不直接搬用官方文件。

### 建议统一的画面规则

背景延续 #08090B / #14161A；正文 #F5F5F7，次级文本保持可读；强调色来自蓝色 OLED，避免全屏蓝紫渐变。外壳保持打印塑料，不改成不存在的镜面金属。实体 PCB 与线束可以保留各自真实颜色，颜色精简指界面不乱，不是把所有器件染成蓝色。

网页正文 16–20 CSS px、主要标题按容器 clamp；关键标签不靠 9 px 半透明小字。字体使用系统栈，中文重点在字面、行高、断行与字重；不分发 Apple 字体文件。在 Windows 与 macOS 实机比较换行，不凭一个平台的标题宽度定死所有布局。

96 秒成片的 1080p 字幕建议 40–48 px 起步，说明标签约 22–28 px；这些是投影候选，要在答辩场地试读。文字避开脸、双端面与手接触区域；影片使用字幕安全区，网页用独立 DOM 文本，不给移动端硬塞一张 16:9 图上的小字。

声音用轻微结构移动、状态提示和克制的音乐；不要给不可闻的超声编造“真实录音”。最终交付同时有无配乐版，以免现场讲解与音乐冲突。使用合法音乐与音效，保存许可。

## 14｜视频输出：选可靠链路，而不是现场赌渲染

### 推荐双轨产出

高质量人物/手部/房间镜头可离线渲染为视频，机器人结构与自由探索保持实时 3D。两者共享资产版本、坐标、镜头和事件定义，但不要求所有离线材质与灯光一比一运行于浏览器。程序外观含 onBeforeCompile 材质，导出 GLB 不会自动保留这类自定义着色逻辑；需烘焙或在离线场景重新建立材质，不能把代码纹理“自动带过去”当既成事实。

先完成 8–12 秒的真实比例房间+手部画质试片，测一次导出成本，再决定完整离线渲染还是局部混合。不要等 96 秒所有镜头做完才发现渲染、贴图或人物资产不适合目标设备。

### 网页直接导出的备用方案

建立只读导出入口 `?capture=1`，隐藏调试/导航，固定随机种子、输出分辨率、DPR、字体和资源版本。提供 `setTime(t)` 与 `waitReady()`，每帧等待资产、纹理、字体、背景媒体完成后渲染和截图；t=n/fps，不靠 Date.now、scrollTo 速度或 wall-clock screen capture。完整画面含 DOM 字幕时抓合成页面，而不仅录 WebGL canvas。

WebCodecs 是编码工具，并不自动完成可播放文件的全部封装；支持情况需检测，不把“调用 VideoEncoder”当成跨浏览器 MP4 导出已完成。本次首选固定环境逐帧图片加 FFmpeg 封装，或已验证的离线渲染器。网页运行不因此依赖 FFmpeg。[W6][W7]

建议成片：1920×1080、30 fps、H.264/yuv420p MP4，AAC 配音/音乐轨；另有无配乐版、字幕文件与海报。96 s 对应 2880 帧（0 到 2879），不能因重复末帧或混用 25/30 fps 改变总时长。帧序列只作为制作中间文件，不全量塞到手机运行包。

```sh
ffmpeg -framerate 30 -start_number 0 -i frames/%06d.png \
  -c:v libx264 -crf 18 -preset medium -pix_fmt yuv420p \
  -movflags +faststart -an CareRover_Keynote_1080p_silent.mp4
```

命令是示例，需先确认输入尺寸、帧数、色彩空间。制作 SDR 版本并在目标播放器验证黑位和白壳高光，不仅添加色彩标签就声称正确。音乐/配音版本要明确混音与总时长；不能为了图省事让 `-shortest` 悄悄截掉最后的现场交接定格。

影片文件必须能够脱离服务器，在答辩电脑本地播放器直接打开。网页内播放器也可用同一 MP4，用户手动选择进入探索。QA 浏览器操作录像和发布片分别命名、分别验收，不能把 story-tour.webm 重命名就交差。

## 15｜截图录像与验收结果：哪些结论已建立，哪些没有

仓库 RESULTS 记录 Node 37/37、Python 37/37、C++ 十套及浏览器 70 项通过，包含四种视口、84 张关键帧截图、静态降级、上下文恢复、实例选择、触摸滚动和控制台状态。它还记录一段 1440×900、25 fps、56.32 s 的 story-tour.webm。上述是读取到的团队证据摘要；本轮没有成功提取媒体并复播，也没有重新计算其二进制哈希。[S4][S6]

check_story 的实际断言主要看章节索引、DOM 不溢出、文字不遮导航、前方轴、重置不漂移、进入/退出 Inspect、资源请求与上下文恢复。这些有价值，但不会自动发现成人尺度错误、全部部件可见性不足、手部是否可辨认，或完整影片是否跳过关键因果。把这些指标全部 PASS 也不能推出“发布会视觉质量 PASS”。[S17]

性能记录有约 133 calls 的总结，部分快照为 137 calls / 37,206 triangles。可说明当前视图与采样时刻不同；不要为小差值制造严重缺陷。重点是这已超过旧“尽量低于100 calls”的软目标，加入人物/房间后要重新测，而不是沿用现有数字。Chrome 模拟390px不是实体手机 GPU，也不是 Safari；字节总和不是网络实测耗时。[S6]

本轮发现的 R01 说明当前“stale telemetry”覆盖的是整体静默，缺失不同来源时间的组合；已加入可运行反例。截图检查应增加 selected masks / visible area，视频检查应增加时间、事件与可读性验证，仍不能用程序给主观美术自动打最终合格分。

版本证据也要分开：团队构建记录有 precommit source_commit=72ee475、source_dirty=true 的描述，后续 CI 确认7e3a091任务成功。不要把前者说成“固定7e3a091 clean构建”；最终 release manifest 要列匹配的 source、web、asset、video、caption、config 哈希，并明确哪份是 compile_only。

## 17｜下一轮执行顺序与完成定义

第一步锁定基线与需求覆盖表，跑原工程测试并保留结果，不回写固件；R01以独立小提交处理。第二步做时间导演与Deck基本功能，让占位关键帧也能完整96秒自动走完。第三步优先重做Inspect布局和选择镜头，并用对象可见性证据验收。第四步完成真人比例桌面拉远、手部接触—OLED短片，再延展成人跟随与杯子场景。最后完成成片导出、网站嵌入、入口导览和两次离线彩排。

不要同时新增前端框架、音频平台、人体生成系统、物理软线和机器人自主功能。高质量人物/手部素材不足时，先使用同一房间的预渲染/合规素材解决近景，不拿更复杂的程序胶囊蒙混成“写实完成”。若只能交较短片段，仍应诚实标“试片”，不能标96秒发布片已验收。

建议拆成五个可审查改动：A控制台确认新鲜度；B导演/Deck/导出；C探索布局/镜头；D真实尺度情境/手部/OLED；E入口/末尾清理/包与证据。生成视频属于D/E的明确交付项，不能在代码完成后继续留成“待手动录屏”。

现有分支可以作为下一轮开发基线，不建议回退到旧单页查看器。本轮并未完成媒体和WebGL独立复播，不能替当前V4签署最终视觉PASS。修正R01并在完整环境完成上述展示回归后，可评估软件集成合并；实体运动仍独立受G01、实际配置、校准与停止测量约束。网页发布与“机器人允许落地自主演示”不要捆成一次无条件批准。
