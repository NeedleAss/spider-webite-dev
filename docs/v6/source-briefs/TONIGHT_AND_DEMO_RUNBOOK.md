## 二｜不接动力时先检查软件

先 `git status --short --branch`、`git rev-parse HEAD`，fetch后比较变更；保留未提交工作，不force reset。使用项目已有锁定工具环境，不临时全量升级。

PowerShell的Node测试不要假设shell自动展开通配符，可以采用：

```powershell
$tests = Get-ChildItem .\tests -Filter *.test.js | ForEach-Object { $_.FullName }
node --test $tests
py -m unittest discover -s tests -p "test_*.py" -v
py tools\appearance_manifest.py --check
# 有兼容C++17编译器时执行；缺失就记录NOT RUN，不宣称通过
py tools\check_firmware.py
# 只枚举串口，不写设备
py -m serial.tools.list_ports -v
```

上面`py`必须对应项目确认的Python与依赖；有项目`.venv`时用其解释器，不在全局环境盲装新依赖。实际编译/verify/flash按照仓库工具的当前帮助与已核验local profile执行；本手册不填猜测COM或分区写地址。

纯软件演示：在仓库根目录启动 `py -m http.server 8765 --bind 127.0.0.1`，打开产品页 `/presentation/`，浏览器模拟操作台 `/?transport=mock`。这不表示真实设备已连接。

## 三｜构建和烧录前停下来核对

确认主控/CAM实际型号、容量、接线、电源和NVS标定。轮位/方向以当前装配和项目记录为准，不根据左右照片猜。

保存实际设备Flash/NVS备份并验证读回；真实wifi/local配置仅私下保存。`compile_only`包不能直接烧，更不能只把验证标志改成“已核实”。不要为了换网页擦除整片Flash或覆盖标定。

控制台改过JS/CSS就重建并更新对应FFat。产品3D/影片仍在电脑，不打进FFat。CAM未改时核实当前版本即可；是否重刷由实际差异决定，不为了“都最新”同时引入多个变量。

## 四｜按阶梯推进，每层不通过就停在该层

1. **observe/动力隔离：** 两板启动、UART元数据、CAM视频、IMU、OLED、健康、前方状态与网页一致；实际未安装/未标定写明。
2. **架空且可断动力：** 确认每轮中位/方向，手动按住/松开、WS断开而AP仍连、普通停止后新IMU不复活动作。软件target、PWM与轮子停止分别记录。
3. **前置条件齐全后的低速受控动作：** 前后左右、选定转向、目标丢失/重获、已配置的前方保护。速度按实测范围，不能直接把归一化60%称作安全速度。
4. **故障与重复：** IMU/人物数据失效、动作取消、视频与控制通道分离、单viewer、无线无USB十分钟、两次冷启动。
5. **G01：** 安全任务自身停摆时的独立PWM撤销必须实测；同任务240ms检查不够。未通过，不用该未放行固件做现场动力演示。

不要在桌边做故障注入。机器人没有已证明的桌沿检测；影片在桌面拍摄不等于实物可无人看护跑到边缘。

## 五｜两个最容易让明天“看起来坏了”的问题

**网页手势模式占用owner、手势动作要求owner=0。** 当前代码可能识别标签正常却拒绝动作。IDLE不释放owner；不要临场反复点模式。今晚修复并完成受监督交接，或者明天只展示识别/OLED而不走此网页动作路径。不得删除CONTROL_BUSY以求能动。

**视频只允许一个观看端。** 控制电脑镜像投影同一个标签页，不另开电脑/手机第二路MJPEG。第二页默认只读遥测；普通错误不能保证一定是busy，要同时检查CAM和链路。冻结画面不是LIVE；视频只显示“图像已载入”时不能盲操。

## 六｜明天上台前90秒

- 放映电脑的影片、字幕、网页、静态备用已离线可用；浏览器不留旧缓存版本混搭。
- 唯一视频页面、唯一操作人、正确模式和权限；关闭无关控制标签页、串口程序和录制脚本。
- 动力状态、场地范围、实体停止手段可达；初始目标为零，未遗留待执行手势。
- 镜头视野和光照合适，真人手势在有效区域，传感器不是靠UI显示“绿色”来猜正常。
- 本次动作清单已经按同包验证；未验证能力从现场动作里去掉。

影片播放期间不要让真实机器人同时被镜头前的人误触发手势。使用已验证的停止/禁止动作状态，或保持动力隔离；切回真实操作前明确恢复过程。

## 七｜8分钟主流程

| 时间 | 舞台动作 | 现场负责人 |
|---|---|---|
| 0:00–0:15 | 一句话介绍项目 | 主讲 |
| 0:15–2:45 | 播放150秒影片，最后定格 | 放映/主讲 |
| 2:45–4:00 | 自由探索讲视觉、主控、轮系 | 主讲，不操作真实运动 |
| 4:00–4:30 | 切真实操作台，说明图像/识别/目标 | 操作者确认模式和权限 |
| 4:30–5:30 | 已放行手动前后/横移，松手停止 | 操作者、安全协助 |
| 5:30–6:30 | 手势识别或一个已放行自主动作 | 预先排练交接，不临场解锁 |
| 6:30–7:30 | 健康采集/OLED，或讲故障边界 | 主讲；真实数据等待就说采集中 |
| 7:30–8:00 | 停止、待机、结束 | 操作者确认实体与授权 |

如总时长只有五分钟，开场影片从同分镜剪成75–90秒，少讲一个重复动作；不要压掉停止与数据来源说明。

## 八｜故障降级台词与动作

画面卡住：先撤销本端运动、确认实体，说明“视频来源出现异常，我们先保持停止，展示系统如何区分画面与控制状态”。不把最后一帧换成模拟画面冒充实时。

手势识别成功但不动：查看动作/权限原因；不连点。可说明“识别与执行权限是两个阶段”，回到已验证的手动或识别演示。

健康尚未出值：保留采集中/无信号。影片示例数字不能写回真页面。预先记录一段标注真实版本和日期的回放备用，不称现场实时。

动作不符合意图：现场操作者立即停止并确认；无法确认则按已验证方法断动力。后续用离线影片/结构/观察数据继续，不在讲台上改固件。
