# CareRover V7｜回到产品，把关键镜头做对

**定向复审与制作决定 · 2026-09-18**

## 01｜唯一选择：视觉方向回退，工程成果保留

**回到此前获得认可的深色产品发布会方向，撤掉当前真人、房间、桌面和椅子情节。以机器人本体、有序结构、感知效果和操作反馈为主角。** 手势与健康功能保留；完整中性手模只在独立样片通过后使用，不再让异常人体承担演示。

这不是把整个仓库倒回第二版。当前 PR #1 已到 `f6d7969b1e555313802a2476640f762a86d986cc`；视觉参考是此前的 V4 `7e3a091125028a68a292df645dfe2512e489d4c9`。新版统一时间轴、自动影片/逐页/滚动入口、完整进入探索、全角度观察、动态 OLED、操作台和控制保护都应保留。[S1–S3]

“回退”的准确含义是撤回不合格的创作方向，然后在当前代码上重做展示。不能把旧版开壳重叠、摄像头效果简陋或旧控制问题一起恢复。不能 `git reset --hard`，不能抹掉组员未提交内容。

前几轮的问题不只是指令不够长，而是把场景扩展放在了可见质量验收之前。本轮改成：**先交三条短样片，用户看过并接受，再生成长片。** 模型加载成功、关节有骨架、自动测试全绿，都不等于镜头可以上台。

## 02｜这次定位到了什么

### A. 平面展开来自明确的代码，不是审美意见的分歧

当前 `presentation/scene/inspection.js:3–9` 的目标中心表将 15 类零件中的 14 类设置为 `x=0`；仅摄像头为 `x=-0.02`。轮与舵机另外按类型、数组位置排成各自的四格。[S4]

本轮复制该生产文件并核对 Git blob：`722da7b28a2ae409f7ff08d297682c4f71bc8dc8`，3071 字节，匹配。只读审计得到：

| 配置事实 | 结果 |
|---|---:|
| 功能类型数量 | 15 |
| 目标中心位于 x=0 的类型 | 14 |
| 目标中心 X 方向跨度 | 20 mm |
| 目标中心 Y 方向跨度 | 610 mm |
| 目标中心 Z 方向跨度 | 490 mm |
| OLED 与顶盖目标中心差 | Y 140 mm、Z 240 mm |

**这是近乎平面的类型陈列表，不是保留装配拓扑的机械爆炸图。** 数值是“配置的类型中心范围”，不是最终网格包围盒，也不是实测穿模面积。审计脚本与结果在 `evidence/`。[E1]

### B. 剧情中的开壳，仍是另一套旧逻辑

当前 `presentation/story/timeline.js:43–53` 仍只给顶盖、OLED、外壳、主板外框默认位移；其他多数部件保持原位。`scene/robot.js` 的文件哈希仍与 V4 相同，继续消费这套偏移。[S5–S6]

因此，用户反映的“剧情里重叠”与“探索里平铺”对应两条不同路径。只增大探索距离不会修剧情；只隐藏外壳不会恢复正确的爆炸关系。应将它们统一为同一个分组、同一个退出路径定义，不再维护两套互相矛盾的空间安排。

### C. 最新手部已经有骨架，问题不能再解释成“换个模型即可”

当前 `scene/actor.js` 加载 `adult.glb`，收集骨骼，再用手写肢体求解和手掌朝向驱动姿势。手指统一套局部 X 轴弯曲，DISLIKE 有世界 X 轴 180° 腕部旋转；接触阶段迭代移动手腕以追逐计算出来的指尖。[S7]

这提供了骨轴、关节限位、左右手、前臂与手腕配合方面的具体复核位置。代码也有过渡混合，不能简单说它每次都瞬间翻腕。本轮未下载模型复演，**不将某一行代码直接宣判为所有可见断裂的唯一原因**。但可以确定：更精细的皮肤或更大的 GLB，不会自动消除继续由这套运行时逻辑造成的姿势风险。

### D. 扫描与回波仍缺少与目标表面的联系

`sensors.js` 的近景摄像头仍是细线视锥、淡平面、检测角标与扫描线；超声近景仍是一个环沿固定平面折返。`app.js` 还为情境另建三个环，其传播距离使用固定的世界 X 坐标表达障碍位置。[S8–S9]

正确端面和朝向应保留。需要改变的是：光/波到达哪里、被什么遮挡、何时返回、结果如何被看见。单纯将青色改绿色或扩大 bloom，不会让这些关系成立。

## 03｜机械展开：从“摆货架”改成“分级打开装配”

**总览仍应一眼看得出是一台被打开的机器人，而不是十五个被重新摆放的商品。** 以底盘和原装配轴为参照，把部件组织成子装配，再在需要时展开子装配内部。

| 子装配 | 总览应怎样打开 | 何时再细分 |
|---|---|---|
| 顶盖 + OLED | 作为整体沿原上方抬升，保持彼此位置 | 讲屏幕或固定方式时 |
| 外壳 | 先沿可退出方向避让，再有限侧移 | 展示壳体细节时 |
| 主控 + 支架/外框 | 先作为安装组让出，再保持前后关系展开 | 点击主控或支架时 |
| 摄像头 + 安装架 | 保持对应，沿镜头/安装基准有限退出 | 镜头/板件特写时 |
| 各角的轮 + 舵机 | 保留每一角配对；轮沿轴退出 | 解释驱动或滚子时 |
| 电源/底盘 | 保留原上下关系与方位 | 电源或底部探索时 |

这是一份分组提案；真实固定方式、退出顺序和退出轴，以用户将提供的安装图与 CAD 核对。没有确认的路径保留待定，不把为了看得见的轨迹说成真实装配顺序。

### 明确实现方式

用 `assembly-tree` 保存父子、实例和对应关系；用 `explode-paths` 保存轴、局部关键点、阶段与间隙。每帧从不可变 rest TRS 和统一 progress 计算。组外先动、组内后动；顶盖/屏幕同组时相对矩阵不变。轮—舵机按稳定 instanceId 配对，不靠数组序号。

初始紧凑开壳、充分展开、选中聚焦是同一树的不同开放层级，不是三个不同零件清单。部件位置沿有意义的装配方向展开；要让开某个视线，优先改镜头和当前层级，不把部件改换到原机身的另一边。

**分开验收三件事：** 三维非设计穿透、当前镜头的投影遮挡、画面主次。薄壳的包围盒包含内部本来就正常，AABB 相交只能筛风险，不能直接判穿模。也不要求任意 360° 视角完全没有投影遮挡；要求默认总览可读、被讲解的部件关键面可见，并能旋转换角。

路径要检查 0%、25%、50%、75%、100%，以及连续正放和倒放；固定前侧、正面、侧面、顶视都看一次。终态好看而中途穿壳，不能通过。

### 交给制作人的具体样片

先拍 8 秒左右：完整整机停留 → 顶盖组抬升 → 外壳退出 → 内部子装配有限展开 → 停留 → 原路收拢。第一条样片固定摄影机，不用镜头晃动或透明材质掩盖重叠。它通过之后，才加发布会式镜头转动。

## 04｜摄像头：学习“光落到物体上”，不是复制绿色线条

本轮实际打开了 Apple AirPods Pro 的内部结构图和心率传感器特写：前者把内部保留在可识别的产品轮廓中，后者用局部器件与表面细节承担画面重点。[W1–W2] 这不是所有 Apple 镜头的通则，但比“黑底加大字”更贴近本项目应该借鉴的具体表达。

Dyson 官方 V15 视频文字说明强调用照明显露表面碎屑，且效果与环境光、碎屑及表面有关。[W3] 本轮读了该官方页面和文字说明，没有逐帧播放其广告。下面的实现是为 CareRover 提出的制作方案，不冒称复制了 Dyson 的着色器。

### 新视觉样片的五个组成

第一，镜头端面与目标有明确空间关系，使用现有正确传感器锚点。第二，薄扫描光带在目标表面出现，随形体和遮挡变化，而不是只在空气里漂着。第三，主要亮度集中在目标表面，空中体积只是很轻的辅助。第四，亮带有软边、距离衰减和受控高光，不涂白镜头/外壳。第五，扫描结束后退去，留下清楚的四角检测框与简短结果。

目标使用检测画面中的抽象人脸/手势轮廓即可；不再把微型成人摆在机器人旁当场景人物。镜头、目标平面、扫描条带与检测框共享投影和事件时间，不能各画一套。

技术上可将扫描遮罩投到目标材质，或在目标 shader 的局部坐标里计算窄条带；深度测试负责遮挡，薄体积片负责空气中的可见性。光效颜色按单章选择，整页 UI 仍保持克制。摄像头本机没有主动激光发射功能，画面标“感知可视化”，而不是因此改变硬件说明。[S8]

合格样片必须看到“扫到什么”；不合格样片只看到“一个绿色锥体”。颜色或参数只是美术选择，不是实物视场角、波长或标定数据。

## 05｜超声：一个完整事件，比不断循环三个环更清楚

撤掉大房间和桌面后，仍可在摄影棚式场景放一个简单、有厚度的障碍物。它不必是杯子，但必须有真正可见的表面。

**事件顺序：出波 → 命中 → 产生回波 → 返回模块 → 形成停止/距离判断。** 出射与返回是两段独立状态；返回不能早于命中。命中点来自几何求交或已经核对的场景锚点，不使用与当前朝向无关的硬编码 world-X 长度。

几条薄弧/扇形波前优于密集同心环。返回波从命中区开始，方向回到接收区域，宽度与强度可不同；所有波保持正确遮挡。TX/RX 未确认时按模块级说明，不自作主张指定左右端面身份。传播放慢与可见颜色是教学处理，不代表真实声波能被看见。[S8–S9]

后续可以让机器人停止，再做已定义的受限绕行动画；不需要人为增加房间、导航或防跌落剧情。效果事件与整车运动统一时钟，不能一边穿障碍，一边仍显示“已检测”。

## 06｜真实人和手到底怎么做

### 本次只做完整中性手模

**采用 Blender，使用允许用于本项目的完整手掌/五指/前臂资产，在建模软件里完成姿势、接触与动作检查，再烘焙给网页播放。** 这是一条明确的制作路线，不是要求重写网站或今晚学习全套人体雕刻。

交付物应是带源网格、骨架、材质和动作的 `hand_source.blend`，米制 `hand_demo.glb`，来源/许可记录，三个中性光静帧和短动作。OBJ/STL 只给形状；一张照片只给视角；它们都不能直接替代检查过的动画资产。

顺序不能反：先用无复杂皮肤的哑光材质检查形体，再检查蒙皮和关节，最后才加外观。拇指根部、指蹼、指甲、腕部都要看得清。手的前臂自然进入画幅；不要让断截面悬在镜头中央。

### 接触特写的最短可靠路线

先把手型摆正确。手与前臂整体接近，指腹对准传感器表面；只动画必要的少量关节，减速接触、保持、再离开。不要为一个指腹接触引入全身实时求解。接触锚点跟随健康模块，而不是包围盒中心。

检查指甲在手背侧、手腕不过度扭转、指根不折断、手指不穿掌/穿壳、保持段不漂移。求解约束的结果先烘焙为最终变形骨骼动画；重新导入 GLB 检查，网页只采样已通过片段。新资产接入后应移除旧 `actor.js` 的通用手指角度驱动，不能让两套动画同时写骨架。

OLED 与接触使用同一事件：接触前待机、保持时采集、模拟结果出现后统一出值、离开后清空。模拟标识持续可见。光学解释仍按 MAX30102 本机原理，不因参考 Apple 而照搬另一款传感器的参数。

### 完整写实人物是另一条资产流程，不是换皮肤就好

MetaHuman + Unreal 提供专门的完整人物、绑定和动画制作流程，官方明确覆盖写实数字人与影视/实时项目。[W4] 它可以用于以后真正需要人物的影片；但静态模型质量、皮肤/眼睛/头发、骨架与蒙皮、动作重定向、接触和灯光分别需要处理。

“手腕翻了”主要需要复核动画和坐标，不是增加模型面数。本轮不把完整写实人物重新放回交付前置条件，也不以购买软件作为收尾计划。用户所说“Hash bat”尚未明确，不能据此猜一个平台并承诺能修好动作。

## 07｜最新功能怎样保留，而不是越退越旧

当前版本已含完整进入探索、平滑且可打断的聚焦、上下方观察和放大缩小。不要重复将它们写成缺失；真正要重做的是展开空间与选中时的安装参照。[S9]

保留“怎么转，都有范”：前、后、左、右、原地 360°、停稳。正交轮系仍按原几何驱动，不以摄影机转一圈代替机器人转动。手势在检测画面或经审查的手模中呈现，不为演示扩展新动作。

保留自动影片、逐页讲解、滚动参观同一时间轴，保留动态 OLED 和真实生产操作台入口。结尾继续不用旧照片，停在完整机身，为现场实物和操作台交接。影片只使用通过的镜头，不为凑满 150 秒保留不合格内容；可先收为约 100–120 秒，再按讲解需要定长。

视觉回退不得恢复旧的网页强制手势授权。当前 V6 直接手势、手动优先、被动页面不抢权、raw neutral 再准入、release_only 与视频时效等是另一套当前产品决定，应隔离保留并继续回归。[S2]

`app.js` 目前把成人与机器人放在同一个 `Promise.all` 中加载；仅隐藏成人仍然会下载成人资产，并保留对其失败的依赖。新入口应移除 actor import/load/pose、场景和相关默认资源，同时更新影片、海报、字幕、降级链接与缓存版本，防止加载失败后又播放旧的恐怖手部片段。[S9]

## 08｜样片、合并和验收顺序

| 次序 | 必交产物 | 不允许替代的内容 |
|---|---|---|
| 1 | 固定视角有序拆解/收拢短片 | 一张终态无重叠截图 |
| 2 | 表面承接的摄像头扫描短片 | shader 编译成功或改绿颜色 |
| 3 | 命中与返回完整的超声短片 | 环形几何能循环 |
| 4 | 手模三视静帧 + 接触/手势短片 | 模型有骨架、网格面数很高 |
| 5 | 集成 Deck/Scroll/Film 与探索 | 只有一份录屏，网页反向浏览失效 |
| 6 | 最终成片、网页、版本证据 | 将旧影片重命名或沿用旧 PASS |

第 1–3 项是当前优先；手模不过就不入片，不影响机器人结构和操作台解释健康功能。用户未接受短片前，不进行长片批量渲染。校验离线播放、暂停、反向浏览、恢复与手机退出，再交付。

至少检查前侧/正面/侧面/顶视，不用只看摄影机正面的一次遮挡掩盖问题。用户提供安装顺序后，把它转为父子和退出约束，不能又只用来说明文字。

## 09｜本轮完成范围与文件

本轮完成最新 PR、制作决定、关键源码读取，生产展开配置的字节级哈希核验与只读审计，官方产品帧/说明参考，以及本制作文件与 Codex 指令。**没有修改远端、创建/合并 PR、完成新手模/新光效/新影片、操作机器人或重跑完整固件测试。**

最新项目影片通过 GitHub 文本接口读取返回不支持；原始截图/影片二进制也没有取得可校验副本；工作流没有可下载的媒体 artifact。本轮未完整观看最新影片、未运行原站 WebGL，因此不把用户所见手部异常写成我独立逐帧复现，也不作最终视觉 PASS。

本轮实际看过的是 Apple 官方上述两张产品图，读过 Dyson 官方视频页面文字与 MetaHuman 官方说明；未完整复播它们的发布会影片。参考中的美术实现建议属于本项目方案，不冒充已破解原片技术。

软件验证、视觉验收、真机测试继续分开。G01 独立撤销 PWM 等现场门槛没有被本轮打开或关闭。将最新代码保留不等于无需回归，也不等于批准实体运动。[S1–S3]

文件入口：`CODEX_V7_RECOVERY.md` 为执行指令；`HAND_ASSET_BRIEF.md` 给手模制作人员；`contracts/V7_DECISIONS.json` 固定新决定；`evidence/` 是本轮实际运行的配置审计，不是修复补丁。
