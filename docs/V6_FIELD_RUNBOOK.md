# V6 实物端验收与答辩流程

**本机没有连接机器人。以下全部实物结果为 NOT RUN。** Git/ZIP 只是移交软件，不能证明机器人能安全动作。V6 源码、影片与证据入口见 `V6_DELIVERY.md`；实物端 AI 使用 `V6_WINDOWS_AI_PROMPT.md`。

## 1. 同版本接手

| 测试人 / 日期 / 电源与接线核对 | 待填写 |

普通 Git checkout 核验版本；ZIP 运行 `py tools/verify_handoff.py`。两个方式择一，不用旧包覆盖新代码。公开示例配置是 compile_only；真实配置必须沿用现场核验的板卡/接线/分区，不能直接修改验证标记绕过工具。

主控构建时同步打包 FFat（根目录控制台）。V6 新前端与新主控的 `scoped_release` 要一起交付；CAM 的错误响应 CORS 也已改变。展示页、人物与影片不烧进 ESP32，放在演示电脑上。

## 3. 约七分钟的答辩

| 时段 | 主讲动作 | 电脑 / 实物 |
|---|---|---|
| 0:00–0:15 | 一句话介绍项目 | 实物保持已验证的禁止动作状态 |
| 0:15–2:45 | 播放本地 MP4，不手动滚网页 | 提前试音量、全屏与离线播放 |
| 2:45–4:00 | 自由探索：展开→摄像头→主控→轮组→恢复 | 清楚说明结构与信号关系 |
| 4:00–5:20 | 展示真实操作台：来源、视频、控制、松手、反馈 | 只有已放行项目才实际动作 |
| 5:20–6:20 | 直接手势或健康/OLED | 新输入、明确状态、不过度连续操作 |
| 6:20–7:00 | 总结与提问 | 回到停止状态 |

影片播放期间不要让实物同时响应观众或影片中的手势。可以保持已验证的禁止动作状态或动力隔离；切回实物时再按现场已验证的恢复步骤操作。这里不要求先打开网页手势模式。

## 4. 降级

- G01 / 驱动门槛未通过：用影片、结构探索、observe/识别/OLED 和明确标注的模拟台展示，不宣称现场动力验收成功。
- WebGL 或网络问题：本地 MP4 和海报可直接播放；不要临场下载资产。
- 视频失效：停止依赖失效画面的操作，区分视频链路与控制链路；503 由原观看者退出后手动重试。
- 识别到了但没执行：查看拒绝原因；不连点模式、不临场删门禁。
